## モーター設定・電源・負荷の計測

ブリッジに読み取り専用の診断を追加した。`motor_diagnostics_enabled` は既定false。ブリッジと同じ単一スレッドのexecutor内で200msごとに1回のレジスター読み取りを行い、別プロセスでシリアルポートを開かない。追加通信は制御周期に影響し得るため、`read_duration_s` と関節状態の受信周期も確認し、調査後は無効化する。

launch再起動後、記録スクリプトを先に開始してから有効化する。初回約16秒で6モーターのP/I/D、不感帯、起動力、最大／現在トルク制限、保護電流・保護トルク・過負荷設定、動作モード、トルク有効状態を読む。その後7種類の現在値（電圧・電流・負荷・温度・目標／実測エンコーダー・状態）を順次読み取る。各項目の更新間隔は約1.4秒で同時測定ではない。raw値とサンプル時刻を `/so101_follower/motor_diagnostics` へJSONで出力し、記録スクリプトが `motor_diagnostics.jsonl` に保存する。SI単位への換算や負荷率の解釈は機種の資料に照らして行う。

```bash
cd ~/robot_arm
source /opt/ros/jazzy/setup.bash
source install/setup.bash
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
python3 scripts/record_arm_tracking.py --seconds 180 &
TRACKING_PID=$!
ros2 param set /so101_motor_bridge motor_diagnostics_enabled true
wait "$TRACKING_PID"
ros2 param set /so101_motor_bridge motor_diagnostics_enabled false
```

有効化後20秒は静止し、その後launch側でEnterを押す。失敗後も10秒以上記録する。設定読み取りは各ブリッジ起動後1回なので、再計測で設定値も保存したい場合はlaunchを再起動してから行う。レジスターは読み取りのみで、設定値・トルク状態・位置指令の変更は行わない。電流や負荷だけから物体の質量を直接算出することはできない。

## ブリッジ経由のPゲイン調整

利用者のゲイン調整依頼に対応し、ブリッジへ `tuning.shoulder_lift.p` と `tuning.elbow_flex.p` を追加。起動時の値は-1で、自動書き換えはしない。既存の単一スレッドexecutor内でシリアル処理する。指定値は整数1〜32、1回の変更幅4以下、1関節ずつ。元値を初回に読み、`/tmp/so101_gain_changes.jsonl` に書き換え前に保存する。-1指定でそのブリッジ実行中の初回値へ戻す。I/Dやトルク設定は変更しない。Lock=1で揮発的変更を試み、書き換え後に必ず読み戻す。失敗時は直前値の復元を試み、ROSパラメーター更新を拒否する。復元失敗はエラーログへ出す。

この機能追加だけで実機のゲインが調整済みになるわけではない。記録と実機読戻し、追従誤差・振動等の評価が必要。パラメーターが-1でも新しいブリッジ起動時に電源が維持されていれば以前のRAMゲインが残る可能性がある。復元元はログと実レジスターを確認する。電源再投入による復元は実機で未検証。自動的なEEPROM保存は行わない。

## 把持TCP誤差15.8mmの内訳（1793910024）

停止後1793910122のコントローラー目標・実測と稼働中ノードのURDF・TCPオフセットを読み取り、失敗ログの凍結目標と比較。動作指令や設定変更は行っていない。計算した誤差15.7947mmが失敗時15.8mmと一致した。ただし停止瞬間の記録ではなく約97秒後の保持状態による再構成である。

目標（base_link、m）[-0.1835384, -0.1165044, 0.0386739]。
指令関節角でのTCP [-0.1834430, -0.1167027, 0.0388105]、実測関節角でのTCP [-0.1717631, -0.1118841, 0.0292153]。
