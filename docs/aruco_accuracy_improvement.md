# 小さいArUcoの位置・姿勢の揺れへの対応

2cmのID0/ID1を変更せず、実画像100枚で角点推定を比較して改善した。画像640×480、マーカー辺の中央値は約28〜29画素。CameraInfoのK/Dは再校正後の `config/camera/ost.yaml` と一致していた。校正ファイルやユーザー設定の取付オフセットは変更していない。

## 変更

- subpixel補正の窓半径を5→3画素。小さいマーカーで大きすぎる探索範囲を避ける。
- 各マーカーの画像上の角点を、最大5フレームの中央値で推定。前フレームまたは窓の最古フレームから角点が1.5画素以上移動、0.2秒を超える観測間隔、時刻の巻き戻りでリセット。移動を完全に無遅延で追う保証はなく、小さい動きでは履歴が残る。30fpsで約2フレーム（約67ms）相当の遅れが生じ得る。
- 現フレームにないマーカーを履歴から補完しない。ID0とID1は引き続き同じ画像で計測する。TF/Poseのstampは現画像のままなので、値には短時間の時間平滑化が含まれる。
- 最小辺16画素未満は3D推定を停止。これは最低限の品質ゲートであり、16画素で精度が保証される意味ではない。
- ID0/ID1以外は3D TFを出さない。全検出IDの一覧は維持。
- IPPEの二候補比較、回転の連続性とLM再投影最小化は維持。

反映は検出ノードを含むlaunchの再起動が必要。`corner_history_window: 1` で中央値化を無効化できる。変更したYAML項目は `corner_refinement_window`、`corner_history_*`、`min_marker_side_px`。

## 同じ100画像での比較

記録 `log/aruco_accuracy/raw_comparison.npz`。同じ校正値・オフセット・IPPE/LMを使用し、base_link基準の物体原点を計算した。数値は位置のばらつきであって実物に対する絶対誤差ではない。撮影列の物理的な完全静止や真値は独立計測していない。

| 方式 | XYZの標準偏差mm | ペア検出数 |
|---|---|---:|
| 従来：窓5 | 19.25 / 11.59 / 1.74 | 100/100 |
| 窓3のみ | 6.23 / 2.45 / 1.90 | 100/100 |
| 採用：窓3＋5フレーム中央値 | 3.82 / 1.58 / 1.21 | 100/100 |
| AprilTag角点方式 | 6.27 / 3.42 / 5.93 | 100/100 |
| 輪郭角点方式 | 27.81 / 15.91 / 9.58 | 100/100 |

採用方式の処理時間はこのPCで約8ms/画像（比較コード全体）、AprilTag方式は約49ms/画像。採用方式の全範囲はXYZ20.1/8.6/6.1mmで、外れや姿勢の曖昧さが完全に解消したわけではない。9フレーム中央値は大きな上積みがなく遅れが増えるため採用しなかった。再投影RMSが小さくても、単眼平面の姿勢候補が正しい保証にはならない。手法間で平均位置も異なっており、真値なしに「絶対精度が向上した」とは判定していない。

再比較: `source /opt/ros/jazzy/setup.bash` の後、リポジトリルートで `python3 scripts/benchmark_aruco_accuracy.py`。保存した画像には元の2cmマーカーを使用。スクリプトは現時点のmarker_offsets.yamlで座標変換するため、オフセット変更後の結果は以前の平均位置と直接比較しない。

## まだ位置がずれる場合

カメラ校正だけでは、印刷寸法誤差、貼り付け面の反り、ID0の取付オフセットの誤差、単一平面の姿勢の曖昧さは解消しない。今回のID0は画像左端にあり、誤差の影響が出る可能性がある。両マーカーをできるだけ画像中央に配置し、実測した黒枠辺長が20mmか確認する。白い余白を辺長に含めない。マーカー面を剛体の平面に固定する。

28画素程度の四隅だけからの姿勢推定には限界がある。カメラを近づけて画素数を増やすか、ID0を大きくする、またはロボットに複数のマーカーを固定したBoardを使うのが次の改善候補。解像度を変える場合は、その画像サイズ・カメラ設定に合う校正値が必要。ID0と物体ID1は別々に動くため、この2つを一つの剛体Boardとして解いてはいけない。

物体移動チェックの15mm制限は緩めていない。真値がない状態で3.6cmの推定変化を単に許容する変更はしていない。ロボットのゲイン・軌道・実機動作にも変更なし。
